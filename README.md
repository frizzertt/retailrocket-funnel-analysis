# Анализ воронки интернет-магазина

Учебный проект по анализу поведения посетителей интернет-магазина на данных Retailrocket. Цель — определить, какая доля просмотренных товаров попадает в корзину, а затем покупается, с учётом порядка событий и времени между ними.

Анализ и сохранённые результаты находятся в [main.ipynb](main.ipynb). Проект в работе: проверка данных и семидневная воронка готовы; следующий этап — сравнение конверсии по неделям первого просмотра.

## Данные

Источник: [Retailrocket Ecommerce Dataset на Kaggle](https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset), файл `events.csv`.

- Период событий: с 3 мая по 18 сентября 2015 года, UTC.
- Исходный объём: 2 756 101 строка.
- Типы событий: `view` — просмотр, `addtocart` — добавление в корзину, `transaction` — покупка.
- Поля: время события, ID посетителя, ID товара и ID транзакции.

Данные загружаются через `kagglehub` в локальный кеш. Вручную скачивать CSV и создавать папку `data` не требуется. Числа в этом README получены на версии 2 датасета; код загрузки не фиксирует версию.

## Что сделано

1. Изучены типы данных, события, пропуски и временной диапазон.
2. Unix-время в миллисекундах преобразовано в дату и время UTC.
3. Проверены пропуски `transactionid`: у просмотров и добавлений в корзину они ожидаемы, поэтому такие строки сохранены.
4. Удалено 460 полных повторов строк: 366 добавлений в корзину и 94 просмотра. После очистки осталось 2 755 641 событие; полных повторов покупок не обнаружено.
5. Сопоставлены количество событий и число уникальных посетителей.
6. Построена последовательность «просмотр → корзина → покупка» и изучены интервалы между этапами.
7. Рассчитана воронка с общим окном в 7 дней и построен график конверсий.

## Правила расчёта

**Единица анализа — уникальная пара `visitorid` + `itemid` («посетитель–товар»).** Один посетитель, просмотревший три разных товара, образует три пары.

Для каждой пары:

1. Находится первый просмотр в имеющихся данных.
2. Находится первое добавление в корзину строго после этого просмотра.
3. Находится первая покупка строго после найденного добавления.
4. Корзина и покупка должны произойти не позднее чем через 7 дней от первого просмотра. Это общее окно на всю последовательность.

В знаменатель включаются только пары, у которых от первого просмотра до конца выгрузки есть полные 7 дней наблюдения. Первый просмотр должен быть не позже последнего события минус 7 дней. Таким образом, поздние просмотры не снижают конверсию из-за недостаточного времени наблюдения.

Окно в 7 дней — выбранное допущение анализа. Оно ограничивает длинные интервалы между действиями и не является определением пользовательской сессии.

## Результаты

| Этап | Уникальных пар | Конверсия от предыдущего этапа |
| --- | ---: | ---: |
| Просмотр с полными 7 днями наблюдения | 2 042 310 | — |
| Добавление в корзину после просмотра | 43 147 | 2,11% |
| Покупка после добавления в корзину | 15 520 | 35,97% |

**Общая конверсия из просмотра в покупку через корзину — 0,76%.**

Среди рассмотренных пар меньшая доля переходов наблюдается на этапе «просмотр → корзина». Однако сама по себе эта доля не доказывает наличие проблемы в интерфейсе или ассортименте: для объяснения причин нужны дополнительные данные и сравнения.

До ограничения временного окна медианное время от первого просмотра до корзины составляло около 1,5 минуты, от корзины до покупки — 4,3 минуты. Эти интервалы рассчитаны только для пар, достигших соответствующего следующего этапа в исходной воронке за весь период.

## Ограничения

- Конверсии относятся к парам «посетитель–товар», а не к посетителям, заказам или отдельным сессиям. Повторные циклы покупки одной пары отдельно не учитываются.
- Первый просмотр — первый наблюдаемый в выгрузке; действия до начала или после конца периода неизвестны.
- Покупки без наблюдаемой последовательности «просмотр → корзина → покупка» не входят в эту воронку. Это не означает, что такие покупки ошибочны.
- В `events.csv` нет цен, источников трафика и экспериментальных групп. Анализ не оценивает выручку и не устанавливает причины различий в поведении.

## Инструменты

Python, pandas, matplotlib, kagglehub; ноутбук Jupyter в VS Code. Проект выполнялся на Python 3.13 в macOS.

## Как запустить

1. Скачайте или клонируйте репозиторий и откройте его папку в VS Code.
2. Установите расширения **Python** и **Jupyter** от Microsoft.
3. В терминале папки проекта создайте окружение и установите зависимости:

   ```bash
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
   ```

4. Откройте `main.ipynb` и в **Select Kernel** выберите Python из `.venv`.
5. Выполните ячейки сверху вниз через **Run All**. При первом запуске `kagglehub` скачает данные; для загрузки требуется интернет. Повторные запуски могут использовать локальный кеш.

Пакет `ipywidgets` включён в зависимости для отображения полосы прогресса загрузки в ноутбуке. Если он установлен после запуска ядра, перезапустите ядро перед повторным выполнением ячеек.
